===================================================
向量化机会代码分析Agent规范
===========================

.. contents::
   :local:

任务
====

本文档规定了一个负责分析源代码的Agent，用于识别标量区域、循环嵌套和潜在适合向量化的数据结构，特别关注RISC-V向量扩展（RVV）功能。

本Agent规范描述了分析阶段，在此阶段使用循环分析、依赖性检查和模式识别来检查代码的向量化机会。

.. important::
   **绝对禁止**：本Agent规范不描述此仓库中的实际代码分析实现。这仅是一个规范文档，旨在指导外部分析工具的设计和实现。

范围
====

代码分析Agent在优化管道的早期阶段运行，识别可以从向量化转换中受益的代码模式和区域。它关注：

* 具有向量化潜力的标量代码区域
* 适合SIMD操作的循环结构
* 适合向量操作的数据访问模式
* 可以有效向量化的控制流

目标架构
========

该Agent设计用于分析**RISC-V向量扩展（RVV）**的代码，考虑：

* **VLEN**：向量寄存器长度（可配置，通常为128、256、512或1024位）
* **LMUL**：向量寄存器分组（⅛、¼、½、1、2、4、8）
* **SEW**：选定的元素宽度（8、16、32、64位）
* **ELEN**：实现支持的最大元素宽度

有关LLVM中RVV支持的详细信息，请参阅`RISC-V向量扩展 <RISCVVectorExtension.html>`_。

输入
====

该Agent接受以下输入进行分析：

源代码
------

* **C/C++源文件**：主要分析目标
* **Fortran源文件**：用于科学计算工作负载
* **其他编译语言**：任何可编译为LLVM IR的语言

中间表示
--------

* **LLVM IR**：主要分析格式
* **循环元数据**：有关循环属性的信息
* **别名分析结果**：内存依赖性信息
* **性能分析数据**：可选的运行时性能分析信息

架构参数
--------

* **VLEN**：目标向量长度
* **LMUL能力**：可用的向量寄存器分组选项
* **ISA扩展**：启用的RISC-V扩展（V、Zve*、Zvl*）
* **微架构特性**：特定目标的优化参数

输出
====

该Agent产生结构化的分析结果：

向量化候选
----------

被识别为向量化机会的代码区域列表，包括：

* **位置**：源位置或IR指令范围
* **循环属性**：迭代次数、边界、归纳变量
* **数据类型**：元素类型和大小
* **访问模式**：顺序、跨步、聚集/分散
* **置信度分数**：成功向量化的可能性（0.0-1.0）

依赖性分析报告
--------------

对于每个候选区域：

* **数据依赖性**：循环携带的依赖性、内存别名
* **控制依赖性**：条件执行、提前退出
* **归约操作**：归约模式的识别
* **依赖距离**：携带依赖性的距离向量

向量化评估
----------

* **推荐的LMUL**：最佳向量寄存器分组
* **估计加速**：预计的性能提升
* **向量化策略**：要使用的方法（strip-mining、unroll-and-jam等）
* **约束条件**：对齐要求、迭代次数假设

不可向量化的区域
----------------

对于无法向量化的区域：

* **位置**：代码区域识别
* **原因**：特定的阻塞因素（依赖性、不支持的操作等）
* **建议**：可能实现向量化的代码转换

能力
====

1. 循环分析
-----------

该Agent识别和分析循环结构：

**循环分类**

* 计数控制循环与条件控制循环
* 单入口单出口（SESE）循环
* 嵌套循环结构和完美/不完美嵌套
* 循环边界分析（常量、仿射、非仿射）

**归纳变量分析**

* 主要和次要归纳变量的识别
* 识别线性、多项式归纳模式
* 检测归纳变量更新和使用

**迭代次数分析**

* 静态迭代次数确定
* 运行时迭代次数分析
* 迭代次数估计和边界

**循环特征**

* 循环体复杂度（指令计数、操作）
* 循环体内的控制流
* 函数调用和副作用
* 内存访问模式

2. 依赖性检查
-------------

该Agent执行全面的依赖性分析：

**内存依赖性**

* 循环携带的依赖性（RAW、WAR、WAW）
* 跨迭代依赖性
* 内存别名分析
* 指针消歧

**控制依赖性**

* 条件执行路径
* 提前循环退出（break、return）
* 循环变量条件
* 异常处理

**归约检测**

* 关联归约操作（+、*、min、max、&、|、^）
* 需要特殊处理的非关联归约
* 归约变量识别
* 归约模式验证

**依赖距离**

* 多维访问的依赖向量
* 均匀和非均匀步长分析
* 前向和后向依赖性
* 距离边界计算

3. 模式识别
-----------

该Agent识别常见的可向量化模式：

**内存访问模式**

* **顺序访问**：连续内存访问（``a[i]``）
* **跨步访问**：规则步长（``a[i*stride]``）
* **聚集操作**：间接索引（``a[idx[i]]``）
* **分散操作**：间接存储操作
* **广播**：单个值到所有向量元素

**计算模式**

* **逐元素操作**：每个元素的独立操作
* **归约**：跨迭代累积（求和、乘积等）
* **扫描**：前缀操作（前缀和等）
* **直方图操作**：分桶和计数
* **点积和矩阵操作**：线性代数模式

**控制流模式**

* **断言执行**：适合掩码的条件操作
* **选择操作**：三元条件模式
* **最小/最大操作**：基于比较的选择

**数据类型模式**

* 整数操作（有符号/无符号，各种宽度）
* 浮点操作（单精度、双精度）
* 混合类型操作和类型转换
* 饱和算术

4. 复杂度评估
-------------

该Agent评估向量化可行性：

**代码复杂度指标**

* 循环体指令计数
* 控制流复杂度（分支、嵌套条件）
* 函数调用开销
* 内存访问复杂度

**向量化可行性**

* **高可行性**：简单循环，无依赖性
* **中等可行性**：具有可管理的依赖性或断言的循环
* **低可行性**：复杂的控制流或不可向量化的操作
* **不可行**：基本阻塞因素（递归调用、复杂别名）

**成本效益分析**

* 估计向量开销（掩码生成、聚集/分散成本）
* 标量与向量代码大小影响
* 寄存器压力考虑
* 内存带宽利用

**架构适用性**

* 代码模式与RISC-V向量能力之间的匹配
* 基于寄存器压力的LMUL选择
* VLEN利用效率
* 目标配置中的指令支持

分析方法
========

算法概述
--------

该Agent遵循这一高级算法：

1. **循环识别**：查找程序中的所有循环
2. **候选过滤**：按基本向量化标准过滤循环
3. **依赖性分析**：执行详细的依赖性检查
4. **模式匹配**：识别特定的可向量化模式
5. **成本建模**：估计向量化收益
6. **排序**：按预期收益对候选进行优先级排序
7. **报告生成**：产生结构化分析结果

启发式方法
----------

该Agent采用启发式方法进行决策：

* **最小迭代次数阈值**：跳过短循环（通常<4次迭代）
* **复杂度截止**：避免过于复杂的循环体
* **内存访问规律性**：偏好可预测的访问模式
* **架构对齐**：偏好适合RISC-V RVV的模式

置信度评分
----------

置信度分数反映向量化成功概率：

* **0.9-1.0**：高置信度 - 简单、明显可向量化的循环
* **0.7-0.9**：良好置信度 - 可管理的依赖性或条件
* **0.5-0.7**：中等置信度 - 需要高级技术（掩码等）
* **0.3-0.5**：低置信度 - 重大挑战或未知因素
* **0.0-0.3**：非常低的置信度 - 边界情况

限制
====

本规范承认以下限制：

**分析范围**

* 分析仅限于循环级向量化
* 不执行全程序分析
* 过程间分析有限

**依赖性分析**

* 保守的别名分析可能过度报告依赖性
* 间接内存访问可能阻止准确分析
* 动态指针值限制编译时分析

**模式识别**

* 可能无法识别新颖或复杂的模式
* 代码混淆可以阻止模式匹配
* 特定于语言的惯用法可能需要自定义处理

**架构假设**

* 分析假设特定的RISC-V向量能力
* 可能无法推广到其他向量架构
* 可能无法完全捕获微架构细节

示例分析场景
============

场景1：简单循环 - 高置信度
--------------------------

**输入代码**::

    void add_arrays(float *a, float *b, float *c, int n) {
        for (int i = 0; i < n; i++) {
            c[i] = a[i] + b[i];
        }
    }

**分析输出**：

* **向量化候选**：是
* **置信度**：0.95
* **模式**：逐元素操作，顺序访问
* **推荐的LMUL**：1或2（取决于VLEN）
* **估计加速**：4-8x（取决于架构）
* **依赖性**：无
* **阻塞因素**：无

场景2：带归约的循环 - 中等置信度
--------------------------------

**输入代码**::

    float dot_product(float *a, float *b, int n) {
        float sum = 0.0f;
        for (int i = 0; i < n; i++) {
            sum += a[i] * b[i];
        }
        return sum;
    }

**分析输出**：

* **向量化候选**：是
* **置信度**：0.75
* **模式**：归约（求和），逐元素乘法
* **推荐的LMUL**：1
* **估计加速**：3-6x
* **依赖性**：归约携带（由向量归约支持处理）
* **阻塞因素**：无（RVV支持向量归约）

场景3：条件循环 - 低置信度
--------------------------

**输入代码**::

    void conditional_update(int *data, int n, int threshold) {
        for (int i = 0; i < n; i++) {
            if (data[i] > threshold) {
                data[i] = data[i] * 2;
            }
        }
    }

**分析输出**：

* **向量化候选**：是
* **置信度**：0.60
* **模式**：条件更新，需要掩码
* **推荐的LMUL**：1
* **估计加速**：2-4x（掩码开销）
* **依赖性**：无
* **策略**：使用掩码向量操作
* **注意**：效率取决于掩码密度

场景4：不可向量化的循环
-----------------------

**输入代码**::

    int fibonacci_sum(int n) {
        int a = 0, b = 1, sum = 0;
        for (int i = 0; i < n; i++) {
            sum += a;
            int temp = a + b;
            a = b;
            b = temp;
        }
        return sum;
    }

**分析输出**：

* **向量化候选**：否
* **置信度**：0.05
* **模式**：顺序依赖链
* **依赖性**：a和b上的循环携带依赖性
* **阻塞因素**：由于基本数据依赖性，无法并行化
* **原因**：每次迭代都依赖于前一次迭代的结果
* **建议**：如果可能，考虑算法更改

术语表
======

.. glossary::

   VLEN
      向量寄存器长度（位）。确定RISC-V向量扩展中向量寄存器的大小。

   LMUL
      向量寄存器分组（长度乘数）。允许将多个向量寄存器视为单个逻辑寄存器。

   SEW
      选定的元素宽度。向量操作中元素的位宽度。

   ELEN
      最大元素宽度。RISC-V向量实现支持的最大元素大小。

   Strip-mining
      一种循环转换技术，将循环迭代划分为适合向量化的块。

   归约
      将多个值组合为单个结果的操作（例如，求和、乘积、最小值、最大值）。

   聚集/分散
      使用索引向量访问非连续内存位置的向量内存操作。

   断言
      使用掩码寄存器有选择地启用或禁用操作的条件执行。

   循环携带依赖性
      一种数据依赖性，其中循环的一次迭代依赖于前一次迭代。
